# Self Harness

Self Harness 是一个个人工作流反馈系统：持续记录睡眠、体重、任务完成和设备使用，把分散的数据整理为可比较的观察，通过报告和邮件帮助调整日常安排。

## 我们要做什么

围绕个人生活与工作的五类信息，回答四个问题：这段时间发生了什么、相比过去有什么变化、哪些观察值得关注、下一步可以尝试什么调整。

| 信息 | 观察内容 |
| --- | --- |
| 睡眠 | 睡眠长度、实际入睡与起床时段、睡眠分布 |
| 体重 | 体重范围、平均水平和变化 |
| 任务 | 完成内容、待办数量和任务变化 |
| iPhone 使用 | App 使用时长及分布 |
| PC 屏幕 | 应用、屏幕内容类别、主题与专注状态；ActivityWatch 并行参考 |

## 工作流

手机端定时上传睡眠、体重和 App 使用数据，PC 用 ShareX 每 5 分钟截图并由服务器生成结构化视觉分析，同时继续采集 ActivityWatch 作为并行参考；服务器定时获取 Microsoft To Do。数据汇集到采集中心，保留原始文件并转成结构化记录。

各来源的 operator 将细粒度记录整理为周期统计。分析环节读取这些材料，结合历史生成报告，再通过邮件投递反馈。

```mermaid
flowchart LR
    A[手机、PC、To Do] --> B[采集中心]
    B --> C[原始文件与来源数据库]
    C --> D[周期统计材料]
    D --> E[core 分析与 HTML 报告]
    E --> F[可选 Gmail 邮件反馈]
```

## 架构

项目按数据流划分职责，使用脚本、文件、SQLite 和系统定时任务组织自动运行。

| 部分 | 职责 |
| --- | --- |
| interface | 每个来源具有 fetcher、parser、database 和 operator，完成获取、转换、保存和统计 |
| observation | 汇集原始文件与结构化记录，提供统一的数据保存位置 |
| core | 读取周期材料，分析变化并生成报告 |
| email | 投递已保存的报告 |

各来源保留自己的数据结构，通过统一的查询与汇总入口提供材料。服务器、路径、来源地址、授权位置、时区与运行周期通过配置管理。

## 从一天看到一年

日报、周报、月报、季报、半年报和年报都包含五类信息。周期越长，材料越侧重走势、分布和上期变化。

日报和周报展示每日趋势，月报展示每周趋势，季度及以上展示每月趋势。屏幕活动把浏览器展开为网站，与其他应用一起表达时间投入。统计同时提供有效数据量，帮助理解结果的依据。

## 当前进展

已完成五个来源的采集、原始文件归档、结构化入库和多周期 operator，并部署了自动采集与入库任务。固定版本为 `operators-v0.1.0`。

已实现 core 单次报告生成与可选 Gmail 投递：读取 interface 周期材料，经 DeepSeek 分析后渲染并保存 HTML 报告；显式添加 `--send-email` 后通过 Gmail OAuth 发送。代码已推送至 GitHub 并部署到 `/root/test-server`；服务器配置、授权、原始数据、数据库和 Python 环境保留在运行目录，采集服务持续运行。

截图观察 `pc_screen_activity` 已实现：Windows 任务每 5 分钟触发 ShareX，WSL 上传 JPEG；服务器分析器调用 DeepSeek 视觉模型生成严格 JSON，写入 raw 后删除截图，parser 入库。ActivityWatch 的非 AFK 前台窗口负责 PC 计时，截图只为这些活跃区间补充行为、主题和视觉 focus；截图不足时直接使用 ActivityWatch。合成图片已跑通上传、分析、融合、汇总与日报渲染检查。
